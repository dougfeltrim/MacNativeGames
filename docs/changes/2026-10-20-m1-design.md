# M1 improvements: design spec and implementation plan

- Date: 2026-10-20
- Branch: `docs/m1-design`
- Status: documentation only; no runtime or build change
- Design: [2026-10-20-m1-improvements-design.md](../superpowers/specs/2026-10-20-m1-improvements-design.md)
- Plan: [2026-10-20-m1-improvements.md](../superpowers/plans/2026-10-20-m1-improvements.md)

## Problem

The port supported every Apple silicon Mac with macOS 26, but the only M1 number in the repository was negative: the
shader step of the build took about 25 minutes on an 8 GB M1 and swapped while it ran (`build_app.py`, `step_warm_metal`).
Every published frame-rate measurement was on an M4 (about 90 FPS after the shader warm-up); there was no M1 benchmark
and no default tuned for the weakest supported machine. The game inherited the M4/iOS defaults on an M1.

The M1 base (8 GB, 7- or 8-core GPU) differs from an M4 in three ways that matter: much less GPU headroom, much less RAM,
and no fan in the MacBook Air. Defaults written for an M4 therefore cost the M1 more than they cost the M4.

## What this increment adds

A design spec and a step-by-step implementation plan. Both are under `docs/superpowers/` and neither touches the code.
The plan is split so that each later branch of this series implements one independent part of it.

## Decisions in the design

1. **One tier preset, not another knob.** The alternatives considered were documenting the existing environment
   variables (rejected: the player must discover them) and a runtime adaptive engine (rejected: scope and risk).
   The preset is data, two strings per tier, and each explicit environment variable still wins.
2. **Tier 1 is an Apple7 GPU family or less than 12 GB of RAM.** The GPU-family clause covers M1/A14. The RAM clause
   deliberately also covers newer 8 GB machines (for example an M2 Air). A `TOTK_TIER=1|2` override exists for A/B tests
   on one machine.
3. **Tier-1 runtime defaults:** render the scene at 1280x720 and let MetalFX upscale to the 1920x1080 canvas. Tier 2 and
   iOS keep today's defaults.
4. **Build and first launch:** below 16 GB, compile the shader seed with 2 threads instead of one per core, and tell the
   player about the Metal toolchain path, which compiles the shaders into the app once and removes the per-machine work
   entirely. The game's own background warm-up gets the same 2-thread default on tier 1.
5. **Measurement is part of the feature:** `TOTK_BENCH=<frames>`, a `bench_report.py` converter, and
   `docs/m1-benchmarks.md`. The success criteria are measured, not assumed: 60 FPS output at 1080p on the M1 base,
   a shader step without heavy swap, and no regression on M4/iOS.
6. **Nothing here may break the build or the picture.** A missing tier (unknown GPU, unknown RAM) falls back to the
   legacy defaults; a failed warm-up falls back to the game compiling on first start; MetalFX unavailable falls back to
   the game's own upscale.

## Validation

Docs-only change: there is nothing to build or test. The design cites the code it relies on (line numbers in the spec)
so that each following increment can verify its assumptions before changing code. The riskiest assumption —
`TOTK_RENDER_RES` governing the docked TotK scene — is called out for an early check in the implementation plan; the
result is recorded in the tier-1 preset increment.

## Trade-offs

- 720p internal rendering is visibly softer than native 1080p. The preset is tier-gated, `TOTK_RENDER_RES` overrides it,
  and `TOTK_TIER=2` restores the previous behaviour wholesale.
- Picking tier 1 by RAM as well as GPU family may put a newer 8 GB Mac on the conservative preset even if its GPU could
  do more. The alternative (family only) would leave those machines without the low-memory build behaviour they need.
- The preset is decided once at startup; a machine that is thermally throttled mid-session does not change tier. A
  dynamic preset was explicitly out of scope.
