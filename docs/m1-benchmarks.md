# M1 实测

机器：8 GB 内存的 M1（8 核，4 性能核 + 4 能效核），macOS 26，只有 Command Line Tools（没有完整 Xcode / Metal 工具链）。游戏 1.0.0 的启动种子：新基线 `30a1b93` 有 23,353 个 `_b.metal`，21,134 个独立内容；旧基线 `4fdda41` 是 22,643 / 20,572。

本页分两部分。前半部分（打包预热、线程扫描、旧完整构建和旧首次启动）测于原始基线 `4fdda41`；新基线 `30a1b93` 的构建、首次启动和 FPS 在文末“新基线 `30a1b93` 复测”一节，完整过程和限制见 [changes/2026-10-21-remeasure-30a1b93.md](changes/2026-10-21-remeasure-30a1b93.md)。

## 打包时的着色器预热（2026-10-21，旧基线 `4fdda41`）

做法与背景见 [first-launch-shaders.md](first-launch-shaders.md)。这里只记数字。

**线程扫描**：冷存储，每档 1,500 个加随机注释的新源码，机器上同时开着编辑器。

| 线程 | 个/秒 | 每个用时 | 存储增量 | 峰值内存压力 | 交换 |
|---:|---:|---:|---:|---|---|
| 2 | 5.8 | 344 ms | 28.4 MB | WARN | 不变 |
| 4 | 8.2 | 486 ms | 28.5 MB | WARN | 不变 |
| 6 | 9.9 | 604 ms | 28.5 MB | NORMAL | 不变 |
| 8 | 8.4 | 942 ms | 28.5 MB | WARN | +54 MB |

6 个最快。8 个更慢，还多了交换。每个库在共享存储里约 19 KB。

**淘汰检查**：2 线程那档最早编，之后又编了 4,500 个，再抽查 64 个仍 64/64 命中（4 线程档同样 64/64）。共享存储当时约 230 MB（上限约 1.08 GB）。

**完整构建**（同一台 Mac，App 打包到 `~/Downloads/nsw-1`，20,572 个独立着色器、6 个线程、冷存储）：

| 阶段 | 用时 |
|---|---|
| 种子校验/复用 | 12 秒 |
| 程序集、签名、macOS 首次扫描（`--check`） | 2,045 秒（系统扫描 16 GB 的 App，与着色器无关） |
| 预热前检（64 个标题着色器） | 262 秒（缓存冷；其中一个最大的源码单次 216 秒） |
| 主预热（20,572 个独立内容，去重 2,071 个） | 1,692 秒（冷编译 17,423，已有 3,149；编译时间合计 10,092 秒；节流 31 秒） |
| 预热后抽查（新进程） | 64/64 命中，中位 0.18 ms，最大 0.74 ms |

整个预热步骤（预检 + 主预热 + 抽查）1,960 秒（33 分钟）；共享存储从 230 MB 涨到 548 MB，最早编的仍在。

**第二次在同一位置打包**：预热前检 64/64 命中（0.19 ms），整步 2.1 秒（含生成 22,643 行的顺序表），未编译任何东西，工具已从 App 删除，`codesign --verify --deep --strict` 通过。

**打包后的第一次启动**（缓存已热，游戏自己的后台预热用 2 个线程）：

| 项目 | 结果 |
|---|---|
| GPU tier 行 | tier 1：720p + MetalFX（`TOTK_TIER=2` 关闭） |
| `first presented frame` | 进程启动后 32.9 秒（约 14 秒是首次启动导入 64,858 个种子文件） |
| `启动关键管线已就绪` | 等待 8 ms（标题清单的名字与种子对不上，v0 的行没有可预热的；用到时按需编译，全部命中） |
| `管线预热完成` | 22,643 个着色器 + 182 条管线，2 个线程，36.3 秒 |
| 运行时编译调用 | 22,801 次，共享存储只增长 0.2 MB（全部命中） |

## 新基线 `30a1b93` 复测（2026-10-21）

完整方法、背景和限制见 [changes/2026-10-21-remeasure-30a1b93.md](changes/2026-10-21-remeasure-30a1b93.md)。这里只列数字。

**构建**（同一台 8 GB M1，工作目录复用，6 个线程）：

| 阶段 | 用时 |
|---|---|
| 种子准备 | 183 秒（23,353 个变体；13,451 个启动着色器 + 共享清单的其余部分；翻译 23,420，跳过 67，缓存 0） |
| 游戏程序和启动器 | 25 秒 |
| 组装、签名、macOS 检查、预热前检 | 约 28 秒（App 之前检查过：0 秒；前检 64/64 命中 0.21 ms，跳过预热） |
| 合计 | 4 分钟（21:55:53 → 21:59:49） |

冷存储的整轮预热没有重跑：Metal 缓存是全机共享的，清掉会影响其他 App；旧基线的 1,960 秒仍是冷存储的参考值。修好 `TOTK_BENCH` 后重建 48 秒（前检 63/64 命中 0.20 ms，未编译）。

**首次启动**（升级路径：缓存里已有旧基线的库）：

| 运行 | 第一帧（游戏内 / 墙钟） | 后台预热 | 管线 | 编译调用 | 共享存储 |
|---|---|---|---|---|---|
| 升级后第一次 | 4.888 秒 | 135.8 秒 | 1,213 渲染 + 179 计算 | 23,559（预编译 0） | 653,110 → 668,197 KB（+14.7 MB） |
| 第二次，同一 profile | 7.649 秒 | 19.7 秒 | 1,320 渲染 + 179 计算 | 23,355 | +0.07 MB |
| 空 profile，同一缓存 | 7.602 / 8.08 秒 | 20.0 秒 | 1,328 渲染 + 179 计算 | 23,355，全部命中 | 不变 |
| 60 FPS 测试 | 3.086 / 3.54 秒 | 22.6 秒 | 1,328 渲染 + 179 计算 | 23,356，全部命中 | +389 KB |
| 30 FPS 测试 | 3.934 / 4.56 秒 | 17.2 秒 | 1,331 渲染 + 179 计算 | 23,355，全部命中 | 不变 |

第一次启动把新种子的差额补进缓存（旧基线 22,643 → 新基线 23,353，且渲染管线从 182 增到 1,213），一次性 135.8 秒；之后每次 17–23 秒。种子现在从已签名的 App 原地读取（`导入 0 个文件`），旧基线约 14 秒的导入消失；第一帧在游戏时钟 3.1–8.1 秒出现（墙钟 3.5–8.1 秒；旧基线墙钟 32.9 秒）。

**FPS**（tier 1，1280x720 场景 + MetalFX 到 1920x1080，最新存档 `slot_04`，300 帧窗口的最后一窗）：

| 指标 | 60 FPS（默认） | 30 FPS（`TOTK_FPS60=0`） |
|---|---:|---:|
| 平均帧时间 | 11.90 ms（渲染 84.0 fps） | 33.31 ms（30.0 fps） |
| 帧 p50 / p95 / p99 | 11.88 / 13.58 / 14.14 ms | 33.45 / 36.01 / 36.64 ms |
| 超过 16.7 ms | 0 / 300 | 300 / 300（30 FPS 的节奏，不是卡顿） |
| 游戏帧工作时间超过 33.3 ms（不含等待上屏） | 0 / 300 | 0 / 300 |
| GPU p50 / p95 | 10.17 / 11.12 ms | 10.02 / 10.98 ms |
| GPU 每秒工作 | 约 0.85 秒/秒（约 85%） | 约 0.30 秒/秒（约 30%） |
| 保活自旋/帧 | 1.01 | 17.92 |
| 上屏节奏 | p50 16.67，最大 33.33 ms；补帧 83，丢弃 0 | p50 33.33，最大 50.00 ms；600 次中 599 次多停一刷新，丢弃 0 |
| 控制器区间 | 2..3，当前 1 | 2..3，当前 2 |

60 FPS 的 5101–5400 窗口因 1.73 秒系统停顿（上屏节奏最大 1733.23 ms）被排除；上表用的是干净的最后一窗。`bench_report.py` 的“drops”列按 25 ms 阈值计上屏，在 30 FPS 下会误报 299/300（实际上屏 300/300，丢弃 0）；30 FPS 不要引用该列。

**热：新旧基线对比**（GPU 每秒工作 = GPU p50 × 渲染速率）：

| 指标 | 旧 60 FPS | 新 60 FPS | 旧 30 FPS | 新 30 FPS |
|---|---:|---:|---:|---:|
| 帧 p50 | 14.25 ms | 11.88 ms | 33.44 ms | 33.45 ms |
| 渲染速率 | 70.2 fps | 84.0 fps | 30.0 fps | 30.0 fps |
| GPU p50 | 12.24 ms | 10.17 ms | 11.45 ms | 10.02 ms |
| GPU 每秒工作 | 0.86 秒/秒 | 0.85 秒/秒 | 0.34 秒/秒 | 0.30 秒/秒 |

上游让每帧便宜了约 17%（14.25 → 11.88 ms），但 60 FPS 的无上限渲染把余量变成了更多帧（70 → 84 fps），所以默认 60 FPS 下持续 GPU 工作——也就是热——基本不变，约 0.85 秒/秒；30 FPS 降到 0.30 秒/秒，差距从 2.5 倍变为 2.8 倍。散热结论与 [changes/2026-10-21-heat-30fps.md](changes/2026-10-21-heat-30fps.md) 一致；30 FPS 是否成为 tier 1 默认仍未改，等用户决定。
